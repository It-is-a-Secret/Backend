# Git 컨벤션

## 1. 브랜치 전략 (Git Flow)

BlurSome은 Git Flow를 사용합니다.

| 브랜치 | 베이스 | 머지 대상 | 수명 |
|---|---|---|---|
| `main` | — | — | 영구 (프로덕션 배포본) |
| `develop` | `main` | `main` (release 경유) | 영구 (통합 브랜치) |
| `feature/*` | `develop` | `develop` | 단기 |
| `release/*` | `develop` | `main` + `develop` | 단기 |
| `hotfix/*` | `main` | `main` + `develop` | 단기 |

### 브랜치 네이밍

```
feature/<이슈번호>-<한글-설명>
release/<버전>
hotfix/<이슈번호>-<한글-설명>
```

**예시**
```
feature/12-사용자-로그인
feature/34-채팅-메시지-전송
release/1.2.0
hotfix/88-회원-탈퇴-오류
```

### 규칙

- `main`, `develop`에 직접 커밋 금지 — 반드시 PR을 통해 머지
- `develop`이 항상 배포 가능한 상태를 유지하도록 관리
- `feature` 브랜치는 PR 머지 후 삭제

## 2. 커밋 메시지 컨벤션

### 형식

```
<타입>: <제목>

[선택 — 본문]

[선택 — 꼬리말]
```

### 규칙

- 제목은 한국어로 작성, 50자 이하
- 제목 끝에 마침표 없음
- 본문은 "왜" 변경했는지 설명, 줄 길이 72자 이하
- 꼬리말에 관련 이슈 번호 기재: `관련 이슈: #42`

### 타입 목록

| 타입 | 설명 |
|---|---|
| `기능` | 새로운 기능 추가 |
| `수정` | 버그 수정 |
| `리팩토링` | 코드 리팩토링 (기능 변경 없음) |
| `테스트` | 테스트 코드 추가 또는 수정 |
| `문서` | 문서 작성 또는 수정 |
| `설정` | 빌드/환경 설정 변경 |
| `제거` | 코드 또는 파일 삭제 |

### 예시

**좋은 예**
```
기능: 회원 이메일 인증 API 추가

회원가입 시 이메일 인증 절차가 없어 허위 계정이 생성되는 문제를 방지하기 위해
인증 메일 발송 및 토큰 검증 로직을 추가했습니다.

관련 이슈: #15
```

```
수정: 채팅 메시지 저장 시 트랜잭션 누락 오류 해결

관련 이슈: #72
```

**나쁜 예**
```
fix bug          ← 영어, 너무 짧음
기능: 로그인 기능을 구현했습니다.  ← 마침표 있음, "했습니다" 불필요
작업함           ← 타입 없음, 내용 불명확
```

## 3. PR 컨벤션

### PR 제목 형식

```
[타입] 한글 제목
```

**예시**
```
[기능] 회원 로그인 API 구현
[수정] 알림 읽음 처리 오류 해결
[리팩토링] UserService 도메인 로직 분리
```

### PR 본문 템플릿

```markdown
## 작업 내용
- 

## 변경 이유

## 테스트 방법
- [ ] 

## 관련 이슈
관련 이슈: #
```

### 머지 규칙

| 브랜치 방향 | 머지 전략 |
|---|---|
| `feature/*` → `develop` | Squash Merge (커밋 이력 정리) |
| `release/*` → `main` | Merge Commit (릴리즈 포인트 보존) |
| `hotfix/*` → `main` | Merge Commit |

- PR을 열기 전 `develop` 기준으로 리베이스하여 충돌 해결
- 리뷰어 **1명** 승인 후 머지 가능
- 머지는 리뷰어가 수행 (작성자 자가 머지 금지)
- 머지 후 feature 브랜치 삭제

---

## 4. 리베이스 & Force Push 규칙

- `main`, `develop`에 `--force` push 금지
- `feature` 브랜치는 PR 오픈 전 `develop` 기준 리베이스
  ```bash
  git fetch origin
  git rebase origin/develop
  ```
- 공유된 브랜치(`main`, `develop`)에서 `git rebase` 사용 금지

---

## 5. 태깅 (버전 관리)

- 모든 릴리즈 태그는 `main` 브랜치에 생성
- `release/*` → `main` 머지 시점에 태그 생성
- 형식: SemVer (`v<major>.<minor>.<patch>`)

```bash
git tag v1.0.0
git push origin v1.0.0
```

| 변경 유형 | 버전 증가 |
|---|---|
| 하위 호환 불가 변경 | major |
| 하위 호환 가능 기능 추가 | minor |
| 버그 수정 | patch |
