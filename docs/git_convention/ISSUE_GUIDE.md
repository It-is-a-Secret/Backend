# 이슈 작성 가이드

이슈 생성 시 이 문서를 기준으로 작성합니다.

---

## 1. 이슈 유형 선택

작업 성격에 맞는 유형을 선택합니다.

| 유형 | 제목 prefix | 라벨 | 사용 상황 |
|---|---|---|---|
| Feature | `[FEAT]` | `✨ Feature` | 새로운 기능 개발 |
| Bug | `[BUG]` | `🐞 Bug` | 기능 오작동 및 버그 수정 |
| Refactor | `[REFACTOR]` | `🔨 Refactor` | 기능 변경 없는 코드 개선 |
| Chore | `[CHORE]` | `🛠️ Chore` | 빌드·라이브러리·환경 설정 등 기타 작업 |
| Docs | `[DOCS]` | (라벨 없음) | 문서 추가 또는 수정 |

---

## 2. 유형별 본문 양식

### ✨ Feature

```markdown
### ✨ 설명
{추가할 기능에 대해 간결하게 설명}

### 📝 작업할 내용
- [ ] {작업 항목}
- [ ] {작업 항목}

### 🔗 참고 자료
{관련 링크나 문서 경로 — 없으면 섹션 생략}
```

### 🐞 Bug

```markdown
### 🐛 어떤 버그인가요?
{버그에 대해 간결하게 설명}

### ✅ 어떻게 해결하나요?
- [ ] {해결 작업 항목}
- [ ] {해결 작업 항목}
```

### ♻️ Refactor

```markdown
### ♻️ 리팩토링 대상
{예: `com.blursome.user.UserService`의 `findById` 메서드}

### 🤔 개선하려는 점
{현재 코드의 어떤 문제점을 개선하고 싶은지 설명}

### ✅ 작업할 내용
- [ ] {작업 항목}
- [ ] {작업 항목}
```

### ⚙️ Chore

```markdown
### ⚙️ 어떤 작업인가요?
{예: Gradle 의존성 업데이트, .gitignore 보완 등}

### ✅ 작업할 내용
- [ ] {작업 항목}
- [ ] {작업 항목}
```

### 📝 Docs

```markdown
### 📝 어떤 문서에 대한 작업인가요?
{예: README.md, API 명세서 등}

### ✅ 작업할 내용
- [ ] {작업 항목}
- [ ] {작업 항목}

### 💡 왜 필요한가요?
{이 문서 작업이 필요한 이유}
```

## 3. 담당자 라벨

이슈 생성 시 담당자에 따라 아래 라벨을 추가합니다.

| 담당자 | 라벨 |
|---|---|
| 박준선 | `🛠️ 준선` |
| 이원진 | `🤖 원진` |

---

## 4. gh CLI 명령어

```bash
gh issue create \
  --repo It-is-a-Secret/Backend \
  --title "[유형] 제목" \
  --label "라벨명" \
  --body "본문"
```

여러 라벨 지정 시 `--label` 을 반복합니다.

```bash
gh issue create \
  --repo It-is-a-Secret/Backend \
  --title "[FEAT] 회원 로그인 API 구현" \
  --label "✨ Feature" \
  --label "🤖 원진" \
  --body "..."
```

---

## 5. 이슈 생성 후 브랜치 네이밍

이슈 생성 후 작업 브랜치는 아래 형식으로 생성합니다 (`GIT_CONVENTION.md § 1. 브랜치 전략` 참고).

```
feature/<이슈번호>-<한글-설명>
```

**예시**

| 이슈 번호 | 제목 | 브랜치명 |
|---|---|---|
| #2 | API 응답 규격화 | `feature/2-api-응답-규격화` |
| #5 | 회원 로그인 구현 | `feature/5-회원-로그인-구현` |
| #12 | 채팅 메시지 전송 | `feature/12-채팅-메시지-전송` |
